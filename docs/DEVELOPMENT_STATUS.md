# 开发状态与验证范围

本文件记录当前实现范围。GitHub Actions 的单元测试与 APK 编译通过，不等同于 Android 真机、ROM Hook 或第三方格式的全面兼容验证。

## 已接入

- Registry 驱动的屏幕、网络类型、充电、电池电量、节电模式、安装应用状态；同一评估器也可作为动作条件。
- 自动化进入、事件、退出动作，启动后的状态重新评估，以及排队、忽略新运行、取消前次、并行策略。
- 自动化条件树、分支、循环、并行、错误处理、流程调用与返回的结构化编辑；流程参数和全局变量编辑。
- 原子工作区保存；读取失败时阻止覆盖；版本化备份、确认后合并恢复，以及未知功能配置保留。
- 执行期限、协程取消、递归深度和循环次数限制；单条规则评估失败不会中断其他规则。
- Root 与 Shizuku 的有界命令执行；输出限制、进程超时、取消传播。Shizuku 通过独立 UserService 执行命令。
- LSPosed API 102 的 system_server 桥接，签名权限保护，版本检查，仅支持休眠、展开及收起通知栏等明确操作。
- 共用 Capability Broker、执行追踪和诊断采集接口；权限与后台不可用时提供失败信息。

## 导入范围

三个导入器独立注册，保留未支持的原始节点，并生成兼容报告。原始导入输入在应用入口限制为 20 MB。

- MacroDroid：结构导入及部分常用触发器、约束、动作映射，包括屏幕事件、启动、解锁、Toast、剪贴板和打开网址。未实现的动作级约束保留为兼容节点。
- Tasker：XML Task/Profile 与进入、退出关系，部分原生动作映射。条件动作保留完整 XML，避免移除条件后执行。尚未完整实现 Tasker 条件与全部动作代码。
- ShortX：JSON 与 protobuf Rule/RuleList/RuleSetList 外层及部分 Toast 映射；保留禁用、备注和未知 Any 内容。有未实现错误策略或上下文行为的节点保持兼容形式。

兼容节点表示需要后续映射，不能视为可执行的原生动作。尚未承诺 MacroDroid、Tasker、ShortX 全部功能等价执行。

## 验证

CI 执行 engine、runtime、storage、diagnostics、三个 importer 和 Android 平台状态单元测试，并构建 Debug APK。覆盖执行超时、取消、并发状态去重、递归、循环限制、备份保真、未知来源保留和输出管道限制。

真机验证仍需逐项进行：

1. Android 12 及以后系统上的启动、权限拒绝、状态变化、后台运行和进程重启。
2. Root/Shizuku 的授权、服务断开、长命令取消以及大输出。
3. LSPosed API 102 的 android 作用域、system_server 重启后桥接、ROM 私有接口与实际系统操作。
4. 来自真实导出文件的逐功能导入对照；按兼容报告继续增加映射与回归样本。

当前仍需完善完整导入映射、设备适配和产品体验；上述实现范围不能作为整个项目已完成的声明。

## 2026-10-09 后续源码保真与权限展示修复

- ShortX 无法原生转换的动作不再丢失原始的启用/禁用状态、备注及遇错中断策略；原始兼容负载和警告仍保留。增加 JSON 与 protobuf 回归测试。
- 功能列表的权限标记改用注册表的 `resolvedAccessRequirements()`，与配置页使用同一来源；按具体功能列出常规 Android 权限及由能力声明推导的 Root、Shizuku、无障碍、通知监听等权限，不再遗漏非特权权限。
- 权限标记展示的是可能的授权路径，不代表同一功能的 Root 与 Shizuku 两者都必须授权；具体操作仍以实现方式的权限说明为准。
